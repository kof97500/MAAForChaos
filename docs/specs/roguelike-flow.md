# 肉鸽流程设计说明

最后更新：2026-06-09

## 1. 目标

本文档用于定义 `卡厄思梦境` 肉鸽流程阶段的实现思路，重点回答：

- 肉鸽阶段应该如何拆状态
- 哪些部分属于“页面流程”
- 哪些部分属于“策略决策”
- 第一版应该先做到什么程度

当前项目已经基本打通：

1. 主界面
2. 卡厄思页
3. 零式系统页
4. 法典选择
5. 配置队伍
6. 进入肉鸽入口界面

后续复杂度会明显提升，因此需要提前把设计边界划清。

## 2. 核心原则

进入肉鸽后，不再只是“识别按钮然后点击”，而是会同时面对：

- 地图节点选择
- 事件选项分支
- 战斗内出牌
- 奖励选择
- 失败恢复

因此肉鸽阶段必须拆成两层：

### 2.1 流程状态机

负责：

- 当前处于哪个页面或阶段
- 页面之间如何跳转
- 什么时候等待
- 什么时候重试
- 什么时候判定失败

### 2.2 策略决策器

负责：

- 地图路线怎么选
- 事件选项怎么选
- 奖励卡怎么选
- 战斗里先出哪张牌

一句话理解：

- 状态机负责“现在在哪，下一步去哪”
- 策略器负责“在这个场景里该怎么选”

## 3. 建议的肉鸽状态拆分

第一版建议至少拆成下面这些状态。

### 3.1 入口与开局状态

- `肉鸽入口页`
- `初始祝福/选项页`
- `初始确认页`
- `进入地图页`

### 3.2 地图与节点状态

- `地图页`
- `等待进入节点`
- `普通战斗节点`
- `精英战斗节点`
- `事件节点`
- `商店节点`
- `休整节点`
- `首领节点`

### 3.3 战斗状态

- `战斗开始`
- `我方回合`
- `出牌中`
- `等待动画结束`
- `敌方回合`
- `战斗胜利`
- `战斗失败`

### 3.4 奖励与成长状态

- `奖励三选一`
- `遗物/装备选择`
- `事件奖励页`
- `战后确认页`
- `返回地图`

### 3.5 异常状态

- `加载中`
- `未知页面`
- `弹窗打断`
- `超时恢复`

## 4. 第一版 MVP 范围

如果目标是“稳定过第一层拿奖励”，不建议一开始就做通用高智能策略，而是收敛到一个足够保守的 MVP。

### 4.1 第一版建议支持

- 固定法典：默认 `01`
- 固定队伍：当前默认配置
- 固定初始选项偏好
- 固定地图路线偏好
- 固定奖励偏好
- 简单战斗规则出牌

### 4.2 第一版先不做

- 多法典适配
- 多队伍构筑
- 高级路线收益评估
- 精细算伤
- 复杂连招优化
- 通用最优策略搜索

## 5. 推荐实现顺序

### 阶段 A：先做外层页面闭环

目标：

- 进入肉鸽入口后，继续完成最开始的开局操作

建议顺序：

1. 识别当前这张肉鸽入口界面
2. 处理初始事件/祝福页面
3. 进入第一张地图页

这一阶段先不碰战斗，只做外层导航。

说明：

- 如果肉鸽入口后的第一页属于事件页，优先按 [event-system.md](/Users/michael/Documents/MaaLearn/docs/specs/event-system.md) 的流程处理：
- 先识别事件页
- 再点击左侧事件信息按钮读取真实事件名称
- 然后结合选项文本做决策

### 阶段 B：做地图状态识别

目标：

- 区分当前是不是地图页
- 在地图页选出下一个节点

建议先做最简单策略：

- 如果存在普通战斗节点，优先普通战斗
- 如果存在事件节点，按预设优先级选择
- 暂时不做复杂路线规划

### 阶段 C：做战斗 MVP

目标：

- 能完成简单战斗

建议第一版规则：

1. 先识别当前是否是我方回合
2. 识别可打出的牌
3. 优先打 0 费牌
4. 优先打直接伤害牌
5. 血量危险时优先防御牌
6. 没有明确可打收益时结束回合

注意：

- 第一版不追求最优
- 只追求稳定不乱点

### 阶段 D：做奖励闭环

目标：

- 战斗胜利后能完成奖励领取并返回地图

建议先做固定偏好：

- 卡牌奖励按预设优先级选
- 不明确时选中间或左侧固定项
- 若有跳过，则按配置决定是否跳过

## 6. 策略系统建议

为了避免把策略写死在状态机里，建议后续单独拆一个策略层。

### 6.1 路线策略

输入：

- 当前地图可选节点列表
- 当前血量、资源、层数

输出：

- 目标节点

第一版可以先用简单优先级：

`普通战斗 > 事件 > 休整 > 商店 > 精英`

具体顺序后续可以再按你的实际目标调整。

### 6.2 战斗策略

输入：

- 手牌区域
- 费用/能量
- 敌人状态
- 我方生命值

输出：

- 本回合动作序列

第一版建议做成规则表，而不是算法搜索。

### 6.3 奖励策略

输入：

- 可选奖励项
- 当前构筑方向

输出：

- 选哪个奖励

第一版可以先固定成：

- 明确优先项
- 否则选固定位置

## 7. 当前最适合的下一步

按照现在的开发节奏，最合适的下一步不是立刻做“自动打第一场战斗”，而是先把肉鸽入口后的第一页状态收清楚。

建议顺序：

1. 明确“进入肉鸽后第一张页面”到底是什么页面
2. 识别这个页面里的可选操作
3. 把它接成下一个业务闭环
4. 再推进到地图页

也就是说，后续应继续坚持当前方法：

- 识别
- 点击
- 轮询等待
- 结果验证

只是从这里开始，状态机会逐步挂上策略模块。

## 8. 建议的数据与接口边界

为了后续不返工，建议后面逐步引入这些抽象。

### 8.1 页面识别结果

建议统一输出：

- `page_type`
- `confidence`
- `matched_template`
- `capture_path`

### 8.2 可选动作列表

建议统一输出：

- `action_type`
- `target_name`
- `target_rect`
- `score`

### 8.3 策略决策结果

建议统一输出：

- `selected_action`
- `reason`
- `fallback`

## 9. 当前结论

肉鸽阶段不是一个单纯的“继续找图点击”的问题，而是：

- `状态机` 负责页面推进
- `策略器` 负责路线、奖励和战斗决策

第一版最稳的路线应该是：

1. 先把肉鸽入口后的外层页面推进做完
2. 再做地图页识别与简单路线选择
3. 最后再做战斗 MVP

这条顺序能让我们始终围绕“先打通主流程，再补策略质量”推进，而不是一上来就陷入复杂战斗逻辑。
