# 开发流程说明

最后更新：2026-06-08

## 1. 总体原则

本项目采用“先打地基，再扩流程”的开发顺序。

核心原则如下：

- 先做基础运行骨架，再做具体游戏逻辑。
- 先验证窗口连接、截图、输入，再做识别与状态机。
- 先接入日志与实时进度展示，再做复杂功能。
- 每完成一个阶段，都要留下文档、日志样例与可复现验证方式。

这意味着第一步不是直接做“肉鸽第一层逻辑”，而是先做：

- 获取游戏窗口
- 校验分辨率
- 截图
- 点击
- 记录日志
- 在控制台展示实时进度

## 2. 推荐开发顺序

建议按以下顺序推进。

### 阶段 0：项目骨架

目标：

- 建立可运行的工程骨架与文档骨架

需要完成：

- 目录结构初始化
- 运行入口设计
- 配置文件结构
- 日志模块接口
- 控制台进度输出接口

阶段产物：

- 可运行的空白主程序
- 可打印启动日志
- 可输出基础阶段进度

### 阶段 1：窗口控制基础能力

目标：

- 让程序稳定找到并连接 `卡厄思梦境 PC 客户端` 窗口

需要完成：

- 枚举窗口
- 按标题、进程名或窗口类名筛选目标窗口
- 获取窗口句柄
- 读取窗口位置与尺寸
- 校验是否为支持的固定分辨率
- 输出窗口连接结果日志

这是第一优先级，因为后续所有识别、点击、状态机都依赖这一层。

阶段产物：

- `窗口发现 -> 连接 -> 校验` 的完整流程
- 成功/失败日志
- 控制台显示当前连接状态

### 阶段 2：截图与输入验证

目标：

- 验证能稳定截图并准确执行输入

需要完成：

- 从窗口采集截图
- 保存调试截图
- 对固定坐标执行鼠标点击
- 验证点击是否命中预期 UI
- 对不同输入方式做对比测试

阶段产物：

- 稳定截图样本
- 输入方式对比记录
- 选定的默认输入方式
- 固定坐标点击前后截图

### 阶段 3：运行时基础设施

目标：

- 建立后续所有功能都会依赖的通用运行框架

需要完成：

- 统一任务执行上下文
- 统一日志格式
- 统一错误码或异常分类
- 统一步骤计时
- 统一控制台实时进度显示
- 统一失败截图保存逻辑

阶段产物：

- `RunContext`
- `Logger`
- `ProgressReporter`
- `DebugCapture`

说明：

这一阶段建议在窗口控制初步跑通后立刻补齐，不要拖到后面。

### 阶段 4：界面识别基础能力

目标：

- 能识别几个最关键的稳定界面

需要完成：

- 主菜单识别
- 肉鸽入口识别
- 战斗中界面识别
- 结算界面识别
- 弹窗/确认框识别

阶段产物：

- 模板资源第一版
- 识别接口第一版
- 识别结果日志

### 阶段 5：外层状态机

目标：

- 自动完成“进入游戏 -> 进入肉鸽 -> 开始新局”

需要完成：

- 定义状态枚举
- 编写状态转换规则
- 为每个状态增加超时、重试与兜底
- 在控制台显示当前状态流转

阶段产物：

- 第一版状态机
- 外层流程运行日志

### 阶段 6：战斗 MVP

目标：

- 用保守规则完成第一层中的简单战斗

需要完成：

- 识别玩家回合
- 识别可出牌区域
- 识别敌方目标区域
- 识别回合结束按钮
- 实现低风险规则

阶段产物：

- 第一版战斗规则
- 战斗步骤日志
- 失败案例截图

### 阶段 7：奖励闭环

目标：

- 打通“第一层战斗 -> 领奖 -> 退出/重开”

需要完成：

- 识别胜利
- 识别奖励领取界面
- 执行奖励领取
- 决定退出或重开

阶段产物：

- 第一版完整刷取闭环
- 端到端流程日志

## 3. 当前建议的第一步

是的，下一步应当优先做“获取游戏窗口”的逻辑。

建议把它拆成一个最小闭环：

1. 启动程序
2. 扫描当前系统窗口
3. 找到目标游戏窗口
4. 输出窗口标题、句柄、坐标、尺寸
5. 判断是否为支持分辨率
6. 连接成功后保存首张窗口截图
7. 在控制台显示“已连接/未连接”
8. 将结果写入结构化日志

只要这个闭环稳定，后面的截图、点击、识别才有意义。

补充说明：

- “获取游戏窗口” 不属于图像识别
- 它本质上是操作系统窗口控制能力的一部分
- 图像识别从窗口连接成功、能够稳定获取截图之后才开始

因此开发顺序上必须坚持：

1. 先解决窗口连接
2. 再解决截图
3. 再进入游戏界面识别
4. 最后才进入任务状态机与战斗规则

## 4. 日志要求

日志不是附属功能，而是基础功能，必须从第一阶段开始接入。

### 日志目标

- 帮助定位运行到哪一步
- 帮助定位为什么失败
- 帮助还原一次运行过程
- 帮助分析识别误判与超时问题

### 日志分层

建议至少分为以下几类：

- `INFO`
  - 正常流程节点，例如“已连接窗口”“进入战斗界面”
- `WARN`
  - 可恢复异常，例如“模板匹配置信度偏低，准备重试”
- `ERROR`
  - 当前步骤失败，例如“窗口截图失败”
- `DEBUG`
  - 调试细节，例如坐标、置信度、耗时

### 每个重要节点必须记录

至少以下节点必须记日志：

- 程序启动
- 配置加载
- 窗口扫描开始/完成
- 窗口连接成功/失败
- 窗口匹配失败原因
- 分辨率校验结果
- 截图开始/成功/失败
- 首张截图保存路径
- 输入动作开始/完成
- 界面识别结果
- 图像识别失败原因
- 状态切换
- 重试开始/结束
- 超时触发
- 任务成功结束
- 异常退出

### 日志格式建议

建议每条日志至少包含：

- 时间
- 日志级别
- 模块名
- 事件名
- 简短消息
- 可选上下文

示例：

```text
2026-06-08 19:42:11 INFO  window  attach_success  已连接游戏窗口 hwnd=123456 size=1600x900
2026-06-08 19:42:15 WARN  detect  low_confidence  未稳定识别到肉鸽入口，准备第2次重试
2026-06-08 19:42:19 ERROR input   click_failed    点击开始按钮失败 x=1320 y=780
```

## 5. 控制台实时进度要求

除了写文件日志，也需要在控制台实时显示运行进度。

### 控制台展示目标

- 用户能立刻知道程序现在做到哪一步
- 用户能立刻看到是否卡住
- 用户能看到当前阶段、状态、重试次数与耗时

### 建议展示内容

至少展示：

- 当前大阶段
- 当前步骤
- 当前状态
- 当前重试次数
- 最近一次动作结果
- 当前累计运行时间

示例：

```text
[阶段] 外层流程自动化
[状态] 进入肉鸽模式
[步骤] 正在识别肉鸽入口按钮
[重试] 1 / 3
[最近结果] 上一次模板匹配置信度不足
[运行时长] 00:01:24
```

### 展示方式建议

V1 可以先采用最简单方案：

- 控制台持续打印关键进度行
- 每次状态变化时输出一条摘要

后续如果需要更好体验，再升级为：

- 单行刷新进度栏
- 表格式状态面板

## 6. 基础能力优先级

在正式进入游戏逻辑前，优先级建议如下：

1. 窗口发现与连接
2. 分辨率校验
3. 截图
4. 输入
5. 文件日志
6. 控制台实时进度
7. 调试截图
8. 界面识别
9. 状态机
10. 战斗规则

## 7. 阶段验收建议

只有满足以下条件，才建议进入下一阶段：

### 进入识别开发前

- 程序能稳定找到目标窗口
- 程序能稳定获取截图
- 程序能稳定执行一次验证点击
- 日志与控制台进度输出已经接好

### 进入状态机开发前

- 已能稳定识别至少 3 个关键界面
- 每次识别都有日志记录
- 每次状态切换都能在控制台看见

### 进入战斗开发前

- 外层流程已基本稳定
- 失败能留截图
- 可以用日志还原最近一次状态流转

## 8. 下一步建议

下一步最适合做两件事：

1. 建立项目目录骨架与运行入口
2. 编写并实现“获取游戏窗口 + 日志 + 控制台进度”的第一版逻辑
