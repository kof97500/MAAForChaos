# 窗口控制设计

最后更新：2026-06-08

## 1. 目标

为 `卡厄思梦境 Windows PC 客户端` 提供稳定的窗口连接、截图与输入基础能力，作为后续识别与自动化流程的底座。

## 2. 第一阶段目标

第一阶段只关注以下能力：

- 发现目标游戏窗口
- 连接目标窗口
- 读取窗口标题、句柄、位置、尺寸
- 判断是否为支持分辨率
- 将结果记录到日志与控制台

暂不要求第一阶段完成：

- 后台稳定输入
- 高性能连续截图
- 多窗口切换
- 多分辨率适配

## 3. 窗口连接逻辑

建议按以下优先级识别目标窗口：

1. 窗口标题精确匹配
2. 窗口标题包含关键字匹配
3. 进程名匹配
4. 窗口类名匹配

建议程序支持：

- 自动扫描并尝试连接
- 配置文件中指定匹配关键字
- 在多候选窗口时输出候选列表

## 4. 连接成功后的校验项

连接成功后应立刻校验：

- 窗口是否可见
- 窗口是否最小化
- 客户区尺寸是否符合目标分辨率
- 窗口标题是否仍匹配
- 进程是否仍存活

如果校验失败，应：

- 写入 `WARN` 或 `ERROR` 日志
- 在控制台明确显示失败原因
- 不进入后续截图与识别流程

## 5. 分辨率策略

V1 建议只支持一个固定分辨率。

原因：

- 模板资源更稳定
- 点击坐标更稳定
- ROI 区域更稳定
- 可显著降低早期复杂度

后续如需扩展，可采用：

- 多分辨率资源包
- 坐标缩放映射
- 基于锚点的相对定位

## 6. 日志与进度要求

窗口控制阶段必须输出以下信息：

- 窗口扫描开始
- 扫描到的候选窗口数量
- 最终匹配到的窗口信息
- 句柄、标题、坐标、尺寸
- 分辨率校验结果
- 连接成功或失败原因

控制台至少应显示：

- 当前阶段：窗口连接
- 当前步骤：扫描 / 匹配 / 校验
- 当前结果：成功 / 失败

## 7. 第一版输出示例

```text
[阶段] 窗口连接
[步骤] 正在扫描系统窗口
[结果] 发现候选窗口 2 个

[阶段] 窗口连接
[步骤] 正在连接目标窗口
[结果] 已连接 卡厄思梦境 hwnd=123456 size=1600x900
```

## 8. 第一阶段验收标准

满足以下条件即可认为窗口控制第一阶段完成：

- 程序可稳定找到目标游戏窗口
- 日志中可看到完整连接过程
- 控制台可看到实时连接状态
- 程序可正确拒绝不支持的分辨率

## 9. 下一步

窗口连接稳定后，下一步进入：

- 截图能力验证
- 输入能力验证
- 调试截图保存
